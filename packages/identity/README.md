# @capacitor-community/stripe-identity

Stripe Identity SDK bindings for Capacitor Applications.

<!-- rdlabo-docs-omit -->

**Documentation:** [Read the full documentation](https://docs.rdlabo.dev/projects/capacitor-stripe-identity)
<!-- /rdlabo-docs-omit -->

## Install

```bash
npm install @capacitor-community/stripe-identity
npx cap sync
```

Requires Capacitor 8, iOS 15+, or Android API 24+. Web uses Stripe.js. Follow [Configuration](docs/configuration.md) for iOS camera usage and the primary App Icon, Android Material Components theme, and web initialization.

## Usage

See [Configuration](https://docs.rdlabo.dev/projects/capacitor-stripe-identity/docs/configuration) and [Identity Verification Sheet](https://docs.rdlabo.dev/projects/capacitor-stripe-identity/docs/identity-verification-sheet).

<!-- rdlabo-docs-omit -->

Your backend creates the VerificationSession and ephemeral key. The app presents the sheet and handles `VerificationResult`; `Completed` means document submission, not a verified identity. Use [Stripe Identity webhooks](https://docs.stripe.com/identity/handle-verification-outcomes) on the server to decide whether verification passed.

```ts
import { IdentityVerificationSheetEventsEnum, StripeIdentity } from '@capacitor-community/stripe-identity';

// Register once per JavaScript application startup, as early as possible during bootstrap.
const verificationResultListener = await StripeIdentity.addListener(
  IdentityVerificationSheetEventsEnum.VerificationResult,
  (result) => {
    console.log(result);
  },
);

// initialize is needed only for Web Platform
await StripeIdentity.initialize({
  publishableKey,
});
await StripeIdentity.create({
  ephemeralKeySecret,
  verificationId,
  // clientSecret is needed only for Web Platform
  clientSecret,
});
await StripeIdentity.present();

// Keep verificationResultListener and remove it only when its application-level owner is destroyed.
```

### Android activity recreation

Register the `VerificationResult` listener once per JavaScript application startup, as early as possible during bootstrap—for example, from `main.ts`, an application initializer, or a singleton service initialized at startup—and before calling `present()`.

On Android, the Activity and JavaScript runtime can be recreated while Stripe Identity is open. If Stripe delivers the verification result to the recreated Activity before the new JavaScript runtime has registered its listener, the plugin retains the result until the bootstrap listener is available.

This is an in-memory handoff of the native result. It is not persistent storage and does not guarantee recovery after OS process death or when Stripe does not deliver a result to the recreated Activity.
